# Windward Mark — project instructions for Claude Code

Read `SPEC.md` before any work. It is the product spec and the source of truth for scope and scoring. `docs/BUILD-PLAN.md` is the phased plan; work one phase at a time.

## What this is
A kiteboarding spot-finder for one rider in the San Francisco Bay Area (derived from Bistué Boarding, the Oregon original in `coastal-kiteboarding`; that app lives in its own repository and is not affected by anything here). The app, tab and home-screen name is **"Windward Mark"** (manifest + title); the repo and URL are `windward-mark`. One screen: spots ranked by a 0–10 score for the selected day, with drive time from Mark's two bases (Paradise Cay in Tiburon, and Candlestick Point in San Francisco where he often rides from; the internal keys stay `LO`/`driveLO` and `BC`/`driveBC` so saved settings keep working) or his current location.

## Hard rules
- **`index.html` is live at https://mikestoneapps.github.io/windward-mark/ and installed on a phone. It must keep working after every change.** Never break the GitHub Pages deploy (branch `main`, root folder). Test the page in a browser before committing; never commit a page that throws on load.
- **Scores never wait for enrichment.** Photos, webcams and station readings load in the background; the ranked list renders from forecasts alone.
- **No AI calls at runtime.** The narrative line is rule-based. Claude is used to write the code, not inside the product.
- **Everything free-tier.** Open-Meteo, NOAA (NDBC, NWS), OpenStreetMap, Wikimedia Commons, GitHub Actions/Pages. Google Maps only behind a server-side key and only on user action. No paid services without asking.
- **Adding a spot requires only name, coordinates and direction sectors.** Everything else optional.
- **Don't re-litigate what the prototype settled** (SPEC.md §10). Keep the house style, **"A1 · Navy band"** (Oct 2026, superseding the original Harbor look): a full-bleed navy (`#0f2236`) header band and dock, the wordmark "Windward <span>Mark</span>" in Montserrat 500 caps with "Mark" in `--wm2`, Montserrat for buttons (filled `#2f9be0` pills), day tabs and score numbers, spot names still in the condensed display face, and the `:root` tokens (light and dark navy) in `index.html`. Riding style reads Foil · Freeride · Wave with **Foil the default** for a new install (a saved style is kept); the sort control is **Score | Distance** (a saved `"tomorrow"` migrates to `"score"`). The synopsis line names places and days only, never figures.
- **Settings sync (phase 2) must not lose what is in the phone's localStorage today**: migrate `goc.settings` and `goc.cache` keys forward.

## Layout of the repo
- `index.html` — the whole app (single file; CSS, markup and JS inline). Fetches Open-Meteo and NWS stations in the browser.
- `img/` — spot photos (480×320 JPEG, CC-licensed; credits in `img/credits.json`). Missing photo ⇒ neutral tile, by design.
- `manifest.webmanifest`, `icon-*.png` — home-screen install.
- `spots.json` — the 27 curated spots (schema in SPEC.md §4; lakes carry `tideStation: null`, and an optional `links` array lists view-only sensor pages riders use, rendered as plain links). `index.html` currently embeds a copy as `const SPOTS`; keep them in sync, or make the page load the JSON (preferred once there is a build step).
- `scoring.js` — the scoring model as a standalone module, identical logic to the page (including comfort limits, per-spot overrides and `consensus()`, the hourly median of best match / ECMWF / NBM that the score runs on). If you change scoring, change both; `node alerts/test.mjs` fails if they differ.
- `stations.json` — nearest public wind (and wave) stations per curated spot, a hand-verified multi-network catalogue (from docs/research/, 2026-10-26). A rider-added spot has no entry: the page's `stationsFor(spot)` pairs it with the nearest wind-capable catalogue rows (up to 3 within 15 mi, distances recomputed from the spot's own coordinates, plus the nearest wave row within 25 mi when it has waves), deterministically and offline, and reuses the readings already fetched for those stations; `rider-stations.json` covers spots outside that footprint. Each row names its feed in `kind`: `nws` (airports), `coops` (NOAA CO-OPS 6-min, the Bay backbone), `ndbc` (buoys), `raws`/`iem` (IEM obhistory), `cencoos` (ERDDAP), `cdec`, `caltrans`, `jpl` (Tahoe buoys), `cdip` (wave only, never wind). These are the **reliable** class: every row they produce in `obs.json` carries `class:"reliable"`. The page embeds it as `NWS_STATIONS` and fetches only the CORS-enabled `nws`/`coops` rows itself. Auto-resolution (`python3 stations.py --resolve`, or Actions → **Resolve stations** since the build container cannot reach NOAA) only ever adds airports and buoys — hand-verified rows are never dropped, and stale MADIS/CWOP mirrors stay excluded. Never add Synoptic, WeatherFlow/iKitesurf, Weather Underground, Holfuy or Windy feeds: their terms forbid it (docs/research/networks.md §5).
- `home_stations.py`, `home-stations.json` — **home (personal) weather stations**, the third class of sensor, run right after `obs_standalone.py`: `kind: "cwop"` (CWOP citizen stations heard over APRS-IS — one read-only TCP connection per run to `rotate.aprs2.net:14580` as WWMARK (several servers refuse the generic N0CALL; a refusal reconnects once to another server), one `r/lat/lon/km` range filter per cluster of spots, 5 min of listening, newest packet per callsign; findu.com raw pages as the fallback when the socket fails, only for catalogued callsigns) and `kind: "netatmo"` (Netatmo public map, `getpublicdata` with `required_data=wind`, one call per area, OAuth from a refresh token; silent without `NETATMO_CLIENT_ID` / `NETATMO_CLIENT_SECRET` / `NETATMO_REFRESH_TOKEN`; the rotated refresh token is kept on the sync Worker under `/v1/admin/vars/netatmo_refresh_token`; setup in `docs/SETUP-NETATMO.md`). Every station ever heard is documented permanently in `home-stations.json` (id, kind, position rounded to 3 decimals, place when known, first/last seen — never dropped, nothing about any rider). Each spot — curated and rider-added alike, from `spots.json` plus `rider-stations.json`, re-attached from coordinates every run — gets the nearest up to 3 home stations within 10 mi that read this run, as ordinary obs.json rows plus `class:"home"` and `trusted:true/false`; the CWOP filter areas and Netatmo boxes grow with the spots, so a new far-out rider spot widens them on the next run. Names: "Tiburon home station (CWOP WB6TTB)" (place only when the catalogue carries one), "Home station (Netatmo) · Belvedere". Home readings never reach the score or the disagreement flag; the page shows them as a secondary, labelled hint from day one. **Not added, their terms forbid redistribution or allow owners only: Weather Underground, WeatherFlow/Tempest/iKitesurf, Ambient Weather, Davis WeatherLink, Holfuy, Synoptic** (networks.md §5). `python3 test_home_stations.py`.
- `home_trust.py`, `home-trust.json` — earned, per-station trust, re-scored hourly on a 30-day window from the `class:"home"` lines in `accuracy.jsonl`: paired samples vs the nearest reliable station within 15 mi that read 5+ kn the same hour (median ratio home ÷ reliable, share within ±30 %), median |home − consensus forecast|, uptime. **Trusted when n ≥ 40, median ratio 0.75–1.3 and ≥ 60 % within ±30 %** (named constants `MIN_N`, `RATIO_LO/HI`, `WITHIN`, `MIN_WITHIN`); a station that degrades loses it, a sheltered one never earns it. The one usage rule lives here too, **`HOME_GAP_MI = 8`** (also in `alerts/lib.mjs`, parity-tested): "Blowing now" (`obs_recent.py` via `home_trust.pick()`) and the bias correction (`bias.py` via `home_trust.select_lines()`) use a trusted home station only when no fresh reliable station is within 8 mi of the spot; untrusted home stations never feed alerts or bias. The forecast score stays model-based; home stations reach it only through `bias.json` under that rule. `python3 test_home_trust.py`.
- `rider_stations.py`, `rider-stations.json` — hourly resolve of stations for rider-added spots (`settings.kept`, read off the sync Worker's `/v1/admin/riders` like the alerts job; skips itself silently without the SYNC secrets): per spot id, the nearest catalogue rows within 15 mi plus freshly resolved airports (25 mi, 35 when nothing is within 25) and buoys (45 mi), capped at 3 wind stations, plus one wave row when the spot has waves. Re-resolved only when the spot's coordinates change; entries nobody keeps are dropped; the file carries only spot id, name, lat, lon and station rows — never anything about the rider. The page merges it into `NWS_STATIONS` at load (same-origin, background, never blocks render); until a far-out spot is resolved its detail says "No sensor yet — readings arrive within the hour". `python3 test_rider_stations.py`.
- `obs_standalone.py`, `stations.py` — fetch station observations for the union of `stations.json` + `rider-stations.json` (station ids dedupe: one request per station per run): one parser per `kind` (see the module docstring for endpoints and unit conversions), every kind returning the same row shape in knots, a failing kind skipped rather than fatal. NDBC, CDEC, JPL and friends have no CORS, so they must be fetched server-side; `python3 test_obs_standalone.py` tests the parsers offline. `stations.py` holds the resolver and reuses the fetchers.
- `fetch_forecast.py` — reference Open-Meteo fetch (5 models + marine).
- `accuracy.py`, `accuracy.jsonl` — the forecast-accuracy log: the hourly observations job appends one line per spot with a fresh station reading (observed knots beside each model's forecast for that hour; `class:"reliable"`), plus one per fresh home station (`class:"home"`, the raw material of `home_trust.py`), 90-day window, committed with `obs.json`. Rider-added spots log too once `rider-stations.json` names them (it carries their coordinates), and they flow through `obs-recent.json` and the "Blowing now" rule like curated ones — with their own sectors, or any direction when the facing is unknown. `python3 test_accuracy.py` tests it offline. The log starts empty in this edition; the first hourly runs fill it.
- `bias.py`, `bias.json` — Phase 5: per-spot, per-model bias from the log (median of observed − forecast, only at 40+ paired samples), `{spotId: {model: {kn, n}}}`, committed hourly. The page and `scoring.js` add the chosen model's bias to the hourly wind before scoring when n ≥ 40 and |kn| ≥ 2 (`applyBias()`, parity-tested); without the file nothing changes. Home-station lines enter only through `home_trust.select_lines()` (trusted, and no reliable station within `HOME_GAP_MI`). `python3 test_bias.py`.
- `obs_recent.py`, `obs-recent.json` — the last six hourly runs' nearest fresh reliable station reading per spot (or, beyond `HOME_GAP_MI` of any, a trusted home station's, tagged `class:"home", trusted:true`), for the "Blowing now" alert (two consecutive runs inside the rider's wind band from a working sector, `blowingNow()` in `alerts/lib.mjs`, which never fires on a home row that is not marked trusted). **Opt-in:** only spots whose 🔔 "Tell me when it blows" button (in the spot's opened detail; a small 🔔 marks them on the collapsed tile) is on can fire — `settings.alerts.blowingSpots`, absent or empty = no Blowing-now alerts at all; picked spots fire whatever their drive time. Its own wind range `settings.alerts.blowMin`/`blowMax` (knots, Alerts sheet; unset = the Rider range), and "Clear all" in the Alerts sheet. `python3 test_obs_recent.py`.
- `checklist-defaults.json` — default checklist items.
- `sync/` — settings-sync + push Cloudflare Worker (`worker.js`, `wrangler.toml`, `test.mjs`). Optional; the page runs on localStorage alone until a Worker URL is entered in the Rider sheet. Also stores push subscriptions, the per-rider "already alerted" state, and small admin-only values a job must keep between runs (`/v1/admin/vars/<name>`: the rotating Netatmo refresh token). Setup in `docs/SETUP-SYNC.md`. The KV id and VAPID key in `wrangler.toml` are placeholders until the Worker is created.
- `alerts/` — hourly push-alert job (`run.mjs` sends, `lib.mjs` decides, `test.mjs` checks the rules and that the page's inline scoring still matches `scoring.js`). Runs in `.github/workflows/observations.yml` after the observations job, on the branch tip so it sees `obs-recent.json`, `bias.json` and `home-trust.json`; skips itself until the secrets exist.
- `away_spots.py`, `away-spots.json` — the away-mode spot catalogue: OpenStreetMap kitesurf/kiteboard/windsurf features worldwide plus named beaches in the US, Canada and Mexico, fetched weekly from Overpass by `.github/workflows/away-spots.yml` and committed. The page filters this file by drive radius; it never queries Overpass for the list (public mirrors are too slow from a browser). Overpass is only used in the background for shoreline facing and webcams.
- `away/` — tests for the page's away-from-home mode (Phase 4; the code itself is inline in `index.html` under "away from home"). `test.mjs` runs that block under Node with the mock catalogue and OpenStreetMap / Open-Meteo / Commons answers in `fixtures.mjs`; `browser-test.mjs` drives the page in headless Chromium with every external host intercepted (`--live` lets them through) and checks home mode against a baseline copy of the page (`BASELINE_DIR=<dir with main's index.html>`).
- `sw.js` — service worker for push only: shows the notification and opens the app on the right day. No fetch handler, no cache (so it can never serve a stale page).
- `docs/` — build plan and setup notes.

## Conventions
- Plain HTML/CSS/JS for the page; no framework unless a phase needs one and the plan says so. Any build step must still produce a static `index.html` that GitHub Pages serves.
- Python 3 for jobs (GitHub Actions). Keep jobs idempotent; commit generated data files (`obs.json`, `forecast.json`) to the repo so the page can read them same-origin.
- Units: knots for wind, feet for surf, °F for air, miles for distance, America/Los_Angeles for time. Knots are the only wind unit stored, synced, scored or logged; the page converts to mph for display only when `settings.units` is `"mph"` (the `wn`/`wg`/`wrange` helpers), and every wind figure shown carries its unit.
- Spot ids are lowercase slugs; never rename an existing id (localStorage overrides key on it).
- Commit messages: imperative, one line of what and why. Small PRs, one phase step each.

## When unsure
Prefer the simplest thing that keeps the live page working, and leave a note in `docs/BUILD-PLAN.md` under "Open questions" rather than guessing at the rider's preferences (we don't know Mark's quiver, weight or favorite spots yet).
